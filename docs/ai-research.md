# OpenAI 研究解读与追问

## 配置

编辑项目根目录 `D:\tradingknowledge\.env`，保留现有 SEC_USER_AGENT：

```dotenv
OPENAI_API_KEY=在本机填写你的真实密钥
OPENAI_MODEL=gpt-5.4-mini
```

后端在每次请求时读取配置，保存后点击 AI 区域的「检查 AI 配置」即可，无需重启。不要使用 `VITE_` 前缀，不要把密钥提交到 Git 或填入浏览器表单。`.env` 已忽略。文件中存在的配置优先于进程环境变量；没有该字段才使用进程环境变量。

「已配置」只说明读取到配置，不代表账户有额度或模型权限。默认模型为 `gpt-5.4-mini`，可替换为支持 Responses、结构化输出及 reasoning 参数的模型。只有点击生成或发送才会调用，不会因浏览或调整估值自动请求 AI。模型使用单独的 OpenAI API 账户额度。

## 实现

后端 `server/narrative.py` 调用固定的 `https://api.openai.com/v1/responses`，`store=false`，通过 `text.format` 的严格 JSON Schema 返回结构化解读。没有自行配置的代理地址，密钥不下发前端。调用超时、额度、权限、拒答和不完整响应均显示明确错误，不展示残缺报告，也不自动重试收费请求。

官方接口依据：[Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)、[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)、[GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini)。`store=false` 控制该接口的响应存储设置，不代表对服务商所有日志和数据保留政策作出零保留承诺。

| 接口                                  | 行为                                             |
| ------------------------------------- | ------------------------------------------------ |
| `GET /api/ai/status`                  | 配置状态、模型、提示词版本、会话上限；不返回密钥 |
| `POST /api/research/{symbol}/explain` | 当前证据上的简洁解读或连续追问                   |

请求接受 snapshot_id、report_end、mode、question、conversation_id、assumptions，以及可选 capital_inputs、beta_sample、analysis_depth（standard / deep）。服务器从不可变快照读取事实，自己重算估值、WACC 和 Beta，拒绝客户端提交“事实”或历史 assistant 消息。

## 普通 / 深度分析与额度

财报、估值、新闻、宏观和期权 AI 界面均提供模式切换。两种模式使用同一个 `OPENAI_MODEL`，默认 `gpt-5.4-mini`。普通推理默认为 medium（宏观普通为 low），输出上限 6000 tokens；深度为 high，上限 10000 tokens，并要求检查反例、假设敏感性、证据缺口与证伪条件。两者都基于当前快照，不额外检索全网，不保证深度结论更准确。

每次生成与追问按当前模式计量：成功仅扣对应 bucket 一次，先原子预留、失败释放、相同请求编号重放不重复扣次；中断 pending 需要核对。研究保存 / 阅读不扣 AI 次数。套餐周期与手动授权规则见 [ToC P0](toc-launch-p0.md) 和 [账号后台](admin-accounts.md)。本轮没有新增真实模型质量或成本评测。

## 回答结构

1. 一句核心判断。
2. 一至三条最相关解释，每条带引用。
3. 一个继续验证的方向及证据缺口。
4. 后续可追问的问题（由服务器提供当前已支持范围内的问题）。

标签分为「数据事实」「AI 推论」「条件假设」。引用点击后展示计算口径、原始值和 SEC 链接；假设引用明确标为用户输入或模型结果。最新报告期的相对估值使用服务器持久化的 Twelve Data 行情快照和 SEC 数据。P_QUOTE、P_BETA、P_BETA_R2、V_PE/PB/PS 均可引用；报价时间、复权方式、股数时点与估算限制随上下文保存。后端覆盖客户端传入的对比价格，防止冒充供应商报价。行情刷新改变快照后会重置会话。尚未接入一致预期、完整指引和行业数据，不作相应事实断言。

## 数值与引用保护

模型收到的证据账本包含已确定的值、单位、报告期、公式及缺失原因。正文中的具体数字通过 `{{指标ID}}` 占位符引用；服务器校验 ID、引用归属和空值，然后用真实计算值替换。只要引用用户参数或模型估值，服务器就强制标为「条件假设」，不依赖模型自己分类。正文中未通过占位符引用的数字、未知引用、裸露内部 ID 和模型生成链接会被拒绝；将 TTM 误称本财年累计、将用户假设归为官方预测等已知错误也会被拦截。

这不是语义正确性的证明：模型仍可能对真实数据作出不充分推论，中文数量表达、因果关系和行业判断也不能仅靠格式校验彻底验证。页面明确提示研究者复核；上线前需补人工标注评估集及持续抽检。当前不提供买卖指令或自动交易。

发送内容包括：当前公司与报告期、有限历史比较、指标及缺失项、用户问题、会话历史、估值假设与计算结果。SEC 联系邮箱、OpenAI 密钥和完整原始财报文件不发送给模型。Beta 输入先在本地后端回归，模型只接收结果摘要与样本摘要哈希，不接收完整价格序列。

## 会话及导出

公司、报告期、快照或估值/资本成本假设变化后重置会话；后端再次核验上下文哈希。财报和基本面各自独立会话，防止把历史判断移植到新假设。

本地已验证模式的会话最多八轮（包含首轮），闲置一小时失效，单进程内存最多一百个，服务重启不保留；前端切换页面后重新开始。配置 DATABASE_URL 时使用 PostgreSQL 共享会话，按墙钟一小时过期；独立存储实例读取及任务租约已通过隔离 PostgreSQL 测试。线上邮箱登录关闭，尚未完成真实用户跨设备 AI 追问；共享会话存储不等于前端自动续接全部研究参数。可导出当前会话 JSON，包含答案、引用证据、参数、时间、模型、提示词版本、计算版本、usage 和 OpenAI response ID；不会导出密钥。账户归档保存独立于临时会话，归档回读不等于恢复全部研究状态。

本机还保留每分钟十次请求、最多两个并发生成的单进程保护。账户鉴权、归属检查与服务端额度账本已实现；共享限流、pending 恢复、实际 token / 供应商成本仪表盘及全站费用上限尚未完成。取消浏览器请求不会保证已发出的服务商调用停止计费。

## 动态发行人与部分数据

发行人由 SEC 目录 CIK 解析，AI 始终绑定服务器财报快照。基本面请求允许 assumptions=null，此时无估值参数或 DCF 输出，不注册 V_BASE 等模型数值，只解读可得财报与已绑定行情。报告 capabilities 禁止 DCF 时，客户端即便提交参数也被后端拒绝。新股票、报告期、行情快照和假设变化均重置上下文。
