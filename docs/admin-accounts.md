# 账号后台与学院界面

更新：2026-11-10。

本文记录已通过本地验收的账号后台；本次文档提交不包含并行修改的业务代码。数据库 / 云端迁移状态以 [开发交接](HANDOFF-2026-11-10-TOC-BILLING.md) 为准，迁移尚未取得本文所需的远程验证证据。

## 使用入口

- 交易学院：`/#academy`，恢复原有横幅、分类、图文卡片、发布本地文章和阅读弹窗。会员课程正文仍经过服务端校验；本地自建文章和学习进度保留。
- 管理后台：`/#admin`。使用管理员邮箱登录后，「会员与账户 → 我的账户」显示「管理员后台」入口。
- 普通 / 深度分析：财报、基本面估值、新闻、宏观事件详情、期权的 AI 区域，显示可直接点击的两种模式。每次生成与追问采用当前选择，成功后只扣对应的一类额度。深度模式仍使用当前证据快照，不包含额外全网检索。

## 管理员配置

在服务端 `.env` 设置 `CLARORA_ADMIN_EMAILS`（逗号分隔邮箱）或 `CLARORA_ADMIN_USER_IDS`（逗号分隔账号 ID）。示例配置不包含真实管理员邮箱。管理员必须通过现有邮箱登录流程建立会话，每次管理请求都会再次检查权限，移除配置会立即停止该会话的管理权限。

本机 `CLARORA_MODE=local` 由本地一次性链接登录；公网需 `public` 模式、HTTPS 与生产 SMTP。不要将本机模式暴露到公网。账号管理权限与 `BILLING_ADMIN_USER_IDS` 的退款审核权限分别配置；本轮未改变退款权限。

## 手动账号与权限

输入邮箱、会员等级、1–366 天有效期和原因即可添加账号并开通会员。不发送邀请邮件，用户自行用相同邮箱登录。免费等级只添加账号，不降级或取消已有授权；高级 / 专家会员解锁会员课程。手动开通不收款，也不会授予管理员权限。

每笔手动授权在整个指定有效期内共用该等级的一份额度，不按月自动补充；例如 90 天研究会员仍共用 100 次普通与 10 次深度额度。到期自动回到当前其他有效权益或免费等级。当前不提供无限额度、自定义能力、自动续期或账号封禁。

为避免覆盖付款权益或意外重置额度，账号有未结束的授权时拒绝重复开通。手动授权可以填写原因并确认撤销，然后重新开通；付款或退款冻结中的权益需走原付款管理流程。撤销不会删除账号和已保存研究。

## 持久化与审核

本地验收基线沿用 `CLARORA_DATABASE` SQLite 数据库，新增 `manual_grants`、`admin_actions`、`admin_requests` 表，首次访问自动创建。PostgreSQL 迁移正在另一聊天实施，不将本地自动建表说明套用于远程环境。人工开通与支付订单分开；新增账号、发放、撤销均记录管理员 ID、原因与时间，详情页展示最近 100 条操作。

写入使用事务与请求编号去重；同一编号重试返回原结果，改动载荷返回 409。权限检查由后端执行，非管理员不能通过直接 API 或伪造表单授予权限。
